# G4 并行工作：先提醒出图，再做独立任务

## 原则

用户出图是 G4 的瓶颈。  
agent 不能空转，但**必须先把手上的出图任务交出去**，再去做不依赖图片/视频的工作。

```text
提示词完成
  ↓
① 发出图清单 image_batch_request.md
  ↓
② 明确提醒用户：“现在可以开始生成图片”
  ↓
③ 用户开始后，agent 做独立任务
  ↓
④ 用户回传图片
  ↓
⑤ 审图 / 补图 / 进入 G5
```

## 必须说的第一句话

不要埋在长文里，要单独说清楚：

> 现在可以开始生成首帧了。  
> 本轮 ___ 张，优先 ___；提示词在 ___；命名规则 ___；完成后放回 `首帧/`。  
> 你去出图，我这边先做 ___、___、___；这些不依赖图片和视频。

## 独立任务（用户出图时做）

| 任务 | 产物 | 依赖 |
|---|---|---|
| 字幕 | `subtitles.srt` | `vo.csv` |
| 配乐 cue sheet | `cue_sheet.csv` | 段落/时间线/旁白 |
| 成本/任务表 | `tasks.json`、`cost.csv` | 镜头/模型/时长 |
| 来源/授权 | `source_list.csv` | 研究资料 |
| credits | `credits.md` | 来源/AI 声明 |
| 剪辑工程骨架 | 轨道/代理/命名 | 工程规范 |
| 下一批提示词检查 | prompt QA | 镜头表 |
| 终检清单 | `final_qc.md` | 交付规范 |

这些工作都不能改旁白、不能改镜头顺序；只做准备。

## 依赖图片/视频的任务（必须等）

- 首帧审图、补图、重生成；
- 图生视频、视频生成；
- 按实际画面调节奏、调色、抠像；
- 最终合成、字幕压片、终检。

不要提前做，也不要“假装看到了图”。

## 不要做的事

- 不要默默开始别的任务，让用户不知道可以出图；
- 不要把“请出图”放在最后一段；
- 不要替用户调图片 API；
- 不要在用户出图前开始审图；
- 不要因为等图而停工，也不要用空话填时间。

## 用户没开始怎么办

- 只提醒一次；
- 如果用户说“等一下”，就停，不要催；
- 如果用户问“现在做什么”，先回答“先出图”，再说明并行工作。

## 并行工作记录

在 `image_batch_request.md` 底部勾选：

```text
[x] 字幕已生成
[x] 时间线已生成
[ ] 配乐 cue sheet
[ ] 成本表
```

用户回图后，先审图，不要重新讨论已经锁定的旁白/镜头。
